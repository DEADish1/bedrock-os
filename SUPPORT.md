# Support

Bedrock is pre-release software and must not be relied on as the only copy of important data. Search existing GitHub issues, then use the repository's guided issue forms for reproducible software defects, hardware compatibility reports, or documentation requests. Include the Bedrock version, exact image checksum, platform, expected and observed behavior, and minimal reproduction steps.

Do not post credentials, recovery codes, private keys, pairing codes, tokens, personal filenames, disk serial numbers, public IP addresses, or unreviewed logs. Generate a redacted diagnostic bundle only when requested and inspect it before attaching it.

Security vulnerabilities must not be filed as public issues. Use [GitHub private vulnerability reporting](https://github.com/DEADish1/bedrock-os/security/advisories/new). General support has no guaranteed response time or service-level agreement. Data recovery, legal advice, and unsupported hardware or macOS virtualization are outside the support promise.
