# Bedrock 1.0 scope freeze

The 1.0 product contract is frozen in `release/1.0-contract.json`. Freeze means additions must be deferred unless they are required to satisfy an existing contract, correct a security or data-loss defect, or complete a release-blocking acceptance gate. It does not mean unfinished roadmap items are implemented or accepted.

## Product boundary

Bedrock 1.0 is an amd64 Debian 13 server appliance with UEFI Secure Boot, immutable verified A/B system slots, safe installation media, storage/NAS management, KVM virtual machines, isolated applications, authenticated local and paired remote administration, encrypted backup/recovery, health alerts, UPS shutdown, and documented support boundaries. Every feature remains subject to its roadmap verification gate.

ARM64 and Apple silicon hosts, legacy BIOS, Wi-Fi-only servers, macOS guests, automatic application updates, an unreviewed application catalog, and unqualified hardware RAID are deferred. A deferred feature cannot be reintroduced through an “advanced” control that bypasses the support or security boundary.

## API compatibility

The `/api/v1` paths recorded in the contract are frozen. Before 1.0, new endpoints may be added only when needed by an already in-scope management area. After 1.0, v1 changes are additive: existing paths, meanings, required request fields, stable identifiers, authorization behavior, and error semantics cannot be removed or weakened. Breaking changes require `/api/v2` and an overlap period. OpenAPI is authoritative and must remain machine-checked against implemented routes.

## State migrations and upgrades

The supported upgrade floor is the first installable 0.2 line. Each later pre-1.0 state schema needs a tested forward migration into 1.0. A migration must validate its source, make a bounded backup before mutation, stage output, fsync and atomically commit, record its source/target versions, and be idempotent after interruption. Failure blocks boot-health promotion and retains the previous system slot plus pre-migration state. Downgrade never tries to interpret newer state in place.

## Hardware matrix

The minimum host contract is four amd64 hardware threads, 8 GiB RAM, a dedicated 32 GiB system drive, UEFI Secure Boot, and wired Ethernet. Storage qualification covers named SATA AHCI, NVMe, IT-mode SAS HBA, and separately evidenced hardware-RAID paths. Intel and AMD physical systems, supported NIC families, UPS models, passthrough devices, and RAID controllers remain unqualified until their acceptance reports pass. Virtual QEMU, VMware, and Hyper-V results supplement but do not replace physical evidence.

Changes to this freeze require a reviewed contract revision, roadmap entry, migration and compatibility impact, and release-note disclosure. Silent contract drift is a release blocker.
